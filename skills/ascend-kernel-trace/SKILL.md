# 昇腾算子时间打点

## 先确认能力

解析本 skill 符号链接后的真实路径，向上两级定位本仓。阅读 [当前状态](../../README.md)、[运行与接入](../../docs/quickstart.md)、[打点设计](../../docs/trace-design.md)、[数据契约](../../docs/data-contracts.md)。A3单卡micro-kernel已完成实测；任意业务事件表和跨核严格校准仍需补齐，不将最小闭环扩大为全面支持。

## 已有执行入口

- 设备记录器：`include/akl/trace/recorder.h`。当前每AIV320B、16事件，Flush需要调用方专属UB及无冲突的EVENT_ID0。
- 采集：在仓库根目录运行 `python3 scripts/run_micro.py --device 0 --max-cores 48 --samples 10 --warmup 3 --output results/<新运行名>`，先按运行说明编译并确认空闲设备。
- 分析：`python3 scripts/report.py results/<运行名>`，可在无NPU机器运行。
- 新目标算子事件表需要新增解析适配；现有解码器会严格检查实验的5个事件，不能直接用于任意事件序列。
- 多级字符串和循环命中可使用 [语义打点入口](../../docs/semantic-trace.md)；该新增入口已完成 CPU/浏览器及 CANN A3/A5 编译验证，业务 NPU 运行尚未验收。

## 工作流程

1. 检查目标仓 AGENTS.md、工作区差异、构建入口与待诊断现象。查清芯片、CANN、核类型、launch 和同步。缺事实先只读调查，仅询问真正阻塞项。
2. 读目标路径和调用关系，列出阶段、角色、等待与完成点。区分到达首点、发射、数据可消费与端到端。
3. 验证时钟和单位，运行单核/跨核探针，保存原始64位 tick。无跨核证据就分域显示，跨卡额外校准并给出误差。
4. 首点放在被观测入口同步前，选择最少关键打点；不为图形整齐加全核 barrier。完成测量需匹配实际流水同步，报告附加开销。
5. 以独立库接入：固定版本、显式 buffer、每通道容量、事件表和 launch 生命周期。不挪用业务输出或硬编码 workspace 偏移。目标仓只保留必要接线。
6. 小用例先测正确性与溢出，再跑目标配置。每次运行独立保存，重复点有序号，缺失和丢弃显式保留；完成后再读出及回收记录。
7. 运行关闭、空计时、开启采集对照，报告时间和资源扰动；诊断计时与生产性能分列。
8. 生成摘要 CSV、PNG/SVG、HTML 与可用的 Perfetto 数据；未实现格式明确标记。按 rank/device/核展示，注明时间域、单位、可信度和缺失。由原始数据重建一次并核对。
9. 给出结论、源码位置、证据路径、未定项和可复验建议。不得由时间先后直接推断通信完成或因果。

## 必守规则

- 首点是可观测入口，不是硬件精确启动时刻。
- 同域使用共同 origin，不逐核归零后声称展示起点差异。
- 整数 tick 做差再换单位；未知频率保留 tick，不默认1ns。
- duration CSV 只出阶段图，不恢复不存在的原始起点。
- 不将 -1、缺失、溢出置零，不无依据截断大样本。
- 关闭宏、编译通过与 CPU 测试不等于实机验收。

## 最小交付

目标仓接入差异、时钟/同步依据、manifest、原始事件、至少一张核对过的图、正确性与扰动对照、限制。资源不可用时给出具体阻塞和可复现计划，状态标记未实测。
