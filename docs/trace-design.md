# Kernel Trace 设计

## 模块边界（规划）

```text
目标算子仓
  └─ 少量打点 + 独立 buffer 参数 + 固定版本依赖
       └─ 本仓 include/akl/trace/：设备记录器与时钟后端
            └─ 本仓 host/：分配、回收、导出
                 └─ 本仓 python/akl/：校验、统计、作图
```

设备端不依赖 Python、业务类或固定 workspace 偏移。Host 管理 buffer，launch 完成且记录提交后回收。捕获图和并发流需独立适配。通过固定提交 submodule、CMake 依赖或本地 include 接入；分析不依赖目标仓安装。

## 采集策略

- 每个逻辑通道独占有界记录区，避免全局原子争抢。逻辑 block/subblock 不直接宣称为物理核，映射来源另存。
- 有界本地暂存后批量搬出，直接 GM 后端按硬件验证后选择。记录 UB/寄存器压力；满时记录 dropped，不覆盖旧事件。
- 使用事件 ID、序号与 span ID，支持循环和嵌套；重复事件不能只保留末次。
- mark 默认只读取时间，不暗中加全核 barrier。完成边界使用已有业务同步或显式诊断同步。
- 关闭宏消除设备记录，Host 不分配 buffer；检查生成代码及端到端基线。
- 采集后由 Host 打印摘要；核内 printf 只用于受控小样本。

## 三种时间视图

1. **核内耗时**：同域后减前，保留整数 tick。
2. **同卡统一时间线**：证明或校准跨核关系后用共同 origin，先整数做差再换算。禁止每核减自己的首点后宣称展示起点偏移。
3. **跨卡时间线**：记录映射 `t_ref = a * t_device + b`、方法、残差、误差与有效窗口。未校准时按设备分面，握手法报告往返时延及非对称假设。

“绝对时间”指可比较基准，不默认是 UTC。测到的是到达首个插桩点的偏移，包含入口到该点的路径。barrier 既不自动证明共同时钟，也会改变原始启动形态。

## 时钟探针

先测无入口 barrier 的各核首点，再单独运行同步边界与受控延迟探针。多轮检查单调性、分辨率、频率与跨核差异，记录误差界。无法建立可信映射时保持 unverified；不能凭一次整齐的图宣布同步。

## 数据与图表

遵循 [数据契约](data-contracts.md)。JSON 原始 tick 用十进制字符串，避免浏览器 2^53 精度限制；先整数减 origin 再换单位。

PNG/SVG 与 HTML 共用分析结果，标明时钟域和单位，按 rank/device/core/block/subblock 分行。起点、等待、完整区间和缺失端点分别呈现。区分阶段堆叠与共同基准甘特图。Perfetto 使用相对时间并附元数据，不跨 launch/stream 配对。

旧 duration CSV 导入标为 duration_only，只能画阶段图，不伪造原始起点或跨卡重叠。
